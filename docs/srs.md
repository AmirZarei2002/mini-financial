# SRS سیستم مدیریت مالی شخصی

## ۱. معرفی

**موضوع:** مدیریت مالی شخصی

**هدف:** یک وب اپ فارسی که کاربر با آن درآمد و هزینه‌هایش را ثبت می‌کند، آن‌ها را دسته‌بندی می‌کند، برای هر دسته بودجه می‌گذارد و گزارش ماهانه می‌گیرد.

**کاربران سیستم:** هر فردی که می‌خواهد دخل و خرج شخصی‌اش را مدیریت کند، مثلا دانشجو یا کارمند.

**اپلیکیشن‌های مشابه:** YNAB، Monarch Money، اپ‌های دخل و خرج

## ۲. نیازمندی‌های کاربردی (Functional)

| شماره | نیازمندی |
|---|---|
| FR1 | کاربر بتواند ثبت‌نام کند، وارد شود و خارج شود |
| FR2 | کاربر بتواند حساب‌های شخصی خود (نقدی، بانکی، کارت) را بسازد، ویرایش و حذف کند |
| FR3 | کاربر بتواند خرج و درآمد ثبت کند و برای هر کدام حساب و دسته انتخاب کند |
| FR4 | کاربر بتواند دسته‌بندی بسازد، ویرایش و حذف کند |
| FR5 | کاربر بتواند تراکنش‌ها را بر اساس دسته‌بندی، بازه زمانی و مبلغ جست‌وجو و فیلتر کند |
| FR6 | کاربر بتواند بین حساب‌های خودش پول جابه‌جا کند |
| FR7 | کاربر بتواند برای هر دسته بودجه تعیین کند و هنگام عبور از سقف هشدار بگیرد |
| FR8 | کاربر بتواند اهداف مالی (پس‌انداز) تعریف کند و پیشرفت آن را ببیند |
| FR9 | سیستم داشبورد و گزارش ماهانه (جمع درآمد، جمع هزینه، مانده، نمودار دسته‌ها) نشان دهد |
| FR10 | کاربر بتواند تراکنش تکراری (قبض، اجاره، حقوق، اشتراک) تعریف کند و یادآوری بگیرد |
| FR11 | کاربر بتواند به تراکنش‌ها برچسب بزند |

## ۳. نیازمندی‌های غیرکاربردی (Non-Functional)

| شماره | نیازمندی | توضیح |
|---|---|---|
| NFR1 | امنیت | رمز عبور به صورت hash ذخیره شود و هر کاربر فقط داده خودش را ببیند |
| NFR2 | کارایی و سرعت | صفحات اصلی در کمتر از ۲ ثانیه باز شوند |
| NFR3 | قابلیت استفاده | رابط فارسی، راست به چپ، با تاریخ شمسی و قالب تومان |
| NFR4 | مقیاس‌پذیری | با زیاد شدن کاربران و تراکنش‌ها کند نشود (ایندکس روی جداول) |
| NFR5 | قابلیت اطمینان و نگهداری | داده‌ها از دست نروند و کد قابل توسعه باشد |

## ۴. قوانین دامنه (Domain Rules)

| شماره | قانون |
|---|---|
| R1 | قانون مالکیت: هر حساب، دسته، تراکنش و بودجه فقط متعلق به یک کاربر است |
| R2 | قانون تراکنش: مبلغ تراکنش باید بزرگ‌تر از صفر باشد و نوع آن درآمد یا هزینه است |
| R3 | قانون دسته: هر تراکنش باید یک دسته داشته باشد و نام دسته برای هر کاربر تکراری نباشد |
| R4 | قانون موجودی: موجودی حساب = موجودی اولیه + درآمدها − هزینه‌ها ± انتقال‌ها |
| R5 | قانون انتقال: حساب مبدأ و مقصد نباید یکی باشند |
| R6 | قانون بودجه و هشدار: اگر جمع هزینه یک دسته در دوره از سقف بودجه بیشتر شود، هشدار داده شود |

## ۵. محدوده پروژه

**در این نسخه:** ثبت‌نام و ورود، حساب‌ها، دسته‌ها، تراکنش‌ها، انتقال، بودجه، اهداف پس‌انداز، تراکنش تکراری، گزارش ماهانه.

**خارج از این نسخه:** اتصال مستقیم به بانک، ورود با OTP، خروجی Excel، اپ موبایل.
